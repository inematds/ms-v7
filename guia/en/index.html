What it is

Social media automation without code, without sounding like AI

Adaptation of “Social Autopilot” for the INEMA stack: everything runs inside Claude Code, with providers, brands, and networks configurable in a single config.yaml.

🧬 Brand voice

One brand-voice.md by brand: who you are, your audience, your offerings, real phrases, true stories, and rules for each network. That’s what makes the post sound like you.

🔌 Pluggable providers

Publishing via Metricool (validated), Blotato, or manual copy. Image with flux2-klein or Magnific. Switching providers is one line in the config.

✅ Approval is a feature

Every publication goes through the gate yes / draft / no. Nothing is scheduled without your explicit reply in the conversation.

How it works

Three questions, three options, one "yes"

The daily workflow of /ms-post. The weekly one (/ms-semana) does the same for 5–7 posts at once, with a retrospective based on analytics first.

config.yaml + brand-voice.md→ network · topic · goal→ research into what works→ 3 options in your voice→ visual→ “Schedule?”→ provider schedules
1

/ms-config

Voice interview (one question at a time), active networks, and providers. Once per brand.

2

/ms-post

Today's post. Three questions, three options, a visual, and scheduling.

3

/ms-semana

Last week's retrospective, a table of 5-7 posts to approve, scheduled queue. ~15 min.

4

/ms-reaproveita

A transcript, article, or URL becomes a standalone post for each network.

Prerequisites

What needs to be ready

Only Claude Code is required. Without a publishing provider, the skills deliver ready-to-copy text.

Claude Code

Pro plan or higher. Open it inside the project folder: it reads the CLAUDE.md on its own.

# clone and open
git clone git@github.com:inematds/ms-v7.git ~/projetos/ms-v7
cd ~/projetos/ms-v7 && claude

Metricool MCP (optional)

Schedule Instagram, TikTok, and more. Free plan: 20 posts/month, no LinkedIn/X.

claude mcp add --transport http metricool \
  https://ai.metricool.com/mcp -s user
# later: /mcp → metricool → Authenticate

Media host (optional)

MCP providers only accept direct URLs. The default is a GitHub Release; the skills upload automatically.

gh release upload v1 arquivo.png \
  --repo inematds/midia --clobber
User guide · step by step

From zero to your first scheduled post

Enter all commands below inside Claude Code, in the project folder. Questions are always asked in free text, one at a time.

1

Configure the brand

Create brands/<slug>/brand-voice.md with an interview and fills in the config.yaml. If the brand is already described somewhere, say where: it pre-fills the details and only asks what’s missing.

/ms-config  # voice → active networks → publishing provider → voice test
2

Create today’s post

Answer with the network, topic, and goal. It researches what's working on the network, writes 3 options with a story or number from your file, and you choose.

/ms-post
# 1. Network?      → instagram
# 2. Topic?      → “why read the system prompt”  (or “research what’s trending”)
# 3. Goal?  → followers
3

Approve the visual and the schedule

The visual comes from the configured image provider. Then it shows you the final post with the best time and waits for your response.

# Visual OK?                        → yes
# Schedule? (yes / draft / no)
sim       # schedule with automatic publishing
rascunho  # stays in the provider’s planner; it doesn’t publish
não       # text only, ready to copy
4

Plan your week in 15 minutes

Retrospective of the last 7 days via analytics, three questions for the week, a table of 5-7 posts for you to edit, and the entire queue scheduled with a single "yes."

/ms-semana  # retro → 3 questions → table → “Edit anything or should I approve?” → queue → “Schedule the queue?”
5

Repurpose a video or article

Paste the transcript, file path, or URL. The only question: which networks. Each post stands on its own, never says “in this video.”

/ms-reaproveita https://youtube.com/watch?v=...  # or an .md, .txt, article URL
6

Publish on git

The skills commit at the end of each post. You just push; the history stays in posts/.

git push  # author inematds <inematds@gmail.com>
